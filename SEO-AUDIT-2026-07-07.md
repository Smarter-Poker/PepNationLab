# PepNationLab.com — Full SEO & AI-Discoverability Audit

**Date:** 2026-07-07
**Scope:** Traditional search engine optimization (Google/Bing) plus "answer engine" / LLM discoverability (ChatGPT, Claude, Perplexity, Gemini, Grok).
**Method:** Static analysis of the codebase (`app/`, `next.config.ts`, `robots.ts`, `sitemap.ts`, layout metadata, JSON-LD) cross-checked against the live site (`robots.txt`, rendered HTML, `llms.txt`, sitemap, sample pages).

---

## Executive Summary

PepNationLab is already **well above average** for technical SEO. It has a Next.js metadata layer, dynamic `robots.ts` and `sitemap.ts`, rich JSON-LD (WebSite, Organization, MedicalSubstance, BreadcrumbList, CollectionPage, speakable), an `llms.txt` / `llms-full.txt` pair, per-compound markdown endpoints for LLMs, RSS feed, PWA manifest, security headers, and programmatic local-SEO city pages. This is a strong foundation most competitors lack.

The gains now are concentrated in a few high-leverage areas:

1. **The homepage is a single image with invisible click-zones — it has no crawlable text, no H1, and no real anchor text.** This is the single biggest issue. The most authoritative page on the domain is effectively blank to search engines and completely blank to AI crawlers.
2. **Key content pages (research hub, compound monographs) render their body client-side.** Google can execute JS, but most AI crawlers (GPTBot, ClaudeBot, PerplexityBot, CCBot) do not — so they see empty shells. The `llms.txt` endpoints partly compensate, but the HTML itself should carry the content.
3. **E-E-A-T / trust signals for YMYL health content are thin** — no author/medical-reviewer schema, no `sameAs` entity links, no `lastReviewed` dates.
4. **Structured data is good but incomplete** — several high-value schema types (FAQPage, DefinedTermSet, Dataset, Product, HowTo) are missing or only partially deployed.

Findings below are prioritized **P0 (critical) → P1 (high) → P2 (polish)**, with a dedicated section on AI/LLM discoverability.

## What Already Exists (Strengths — Do Not Break)

- **Metadata layer:** `metadataBase`, unique `title`/`description`/`keywords` per page, canonical URLs, Open Graph + Twitter cards, `og-card.png` (1200×630), per-compound dynamic OG images (`app/research/[slug]/opengraph-image.tsx`).
- **Crawl directives:** Dynamic `robots.ts` (allows public pages, disallows auth/admin/api) and dynamic DB-backed `sitemap.ts` (static pages + ~300 compound monographs + research filters + city pages).
- **Structured data:** Global `WebSite` + `Organization` with `SearchAction` (Sitelinks Search Box), `MedicalSubstance` + `MedicalWebPage` + `BreadcrumbList` on monographs, `CollectionPage` on `/research`, `speakable` spec, ChEMBL/UniProt/UNII codes.
- **AI-native surfaces:** `/llms.txt`, `/llms-full.txt`, per-compound markdown at `/api/llm/compound/[slug]`, `alternates.types['text/markdown']` on monographs, RSS at `/feed.xml`.
- **Infra:** HSTS + full security-header set, 301 host redirects to the canonical domain, PWA manifest, error/404 boundaries.
- **Programmatic local SEO:** State + city landing pages (`/peptides/[state]/[city]`), server-rendered with real `next/link` internal links and unique per-city metadata.

## P0 — Critical (fix first; highest impact)

### P0-1. Homepage has zero crawlable content
`app/HomeClient.tsx` renders one large PNG (hosted on Supabase) with eight absolutely-positioned **empty `<a>` tags** (only `aria-label`/`title`, no visible or textual anchor content). The live HTML for `/` contains no `<h1>`, no paragraph text, and no descriptive link text.

**Why it matters:** The root domain carries the most authority and is sitemap priority 1.0. Google indexes it on meta tags alone; AI crawlers that don't run JS see essentially nothing. All internal link equity from the homepage is passing through anchors with no text, so no topical context flows to `/research`, `/peptide-101`, etc.

**Fix:**
- Add real semantic HTML beneath or layered with the artwork: one `<h1>` (e.g. "Premium Research Peptide Distribution & Peptide Research Library"), a 1–2 paragraph intro, and a visible/crawlable nav.
- Convert the eight click-zones to links with real anchor text (can be visually-hidden with `.sr-only` if the design must stay image-first, but real text must exist in the DOM).
- Add a server-rendered content block: featured compounds, research-area links, "what is a research peptide" explainer — all with internal links using descriptive anchor text.
- Consider replacing the single flat PNG hero with real HTML/CSS so the text is native and the LCP image is optimized.

### P0-2. Core content pages render body client-side
`/research` (`ResearchLandingClient`) and compound monographs (`MonographTabs`) are `'use client'`. Live HTML fetches return only the `<h1>`/title with no body prose.

**Why it matters:** Googlebot renders JS (with delay), but **ClaudeBot, GPTBot, PerplexityBot, CCBot, Bytespider generally do not execute JavaScript.** They index the raw HTML. So the exact pages you most want cited by AI (compound monographs) look empty to them. Also hurts Core Web Vitals and time-to-content.

**Fix:**
- Server-render the primary monograph prose in the initial HTML: summary, mechanism of action, key facts, evidence tier, references. Keep interactivity (tabs, charts) as progressive enhancement — render tab panels in the DOM (e.g. as sections) and let JS enhance them, rather than mounting content only after hydration.
- Same for `/research`: server-render the compound list/grid and area links so the hub is crawlable without JS. `force-dynamic` is fine, but the returned HTML must contain the text.
- This is the highest-ROI change for AI citations, and the `llms.txt` endpoints should remain as a belt-and-suspenders layer, not the only layer.

### P0-3. Verify AI crawlers and Googlebot are not blocked at the edge
`robots.txt` allows `*`, which is correct, but Vercel WAF / firewall rules, bot-fight modes, or Cloudflare-style challenges frequently block `GPTBot`, `ClaudeBot`, `PerplexityBot`, `Google-Extended`, `CCBot`, and even render-phase Googlebot without anyone realizing.

**Fix:**
- Confirm in Vercel project settings that no firewall/attack-challenge rule blocks these user agents. Test with `curl -A "GPTBot" https://pepnationlab.com/research/bpc-157` and `curl -A "ClaudeBot" ...` and confirm real HTML returns (not a challenge page).
- Explicitly decide your policy on `Google-Extended` (Gemini training) and `GPTBot` — if you *want* AI recommendation, keep them allowed. Add them by name to `robots.ts` as explicit `allow` for clarity.
- Note: `/api/llm/compound/[slug]` sits under the `Disallow: /api` rule and returned empty on an external fetch. Make sure the markdown LLM endpoints are reachable — either move them out of `/api` (e.g. `/llm/compound/[slug]`) or add an explicit `Allow: /api/llm` before the `Disallow: /api`.

## P1 — High Priority

### P1-1. E-E-A-T / trust signals for YMYL content
Health/medical content is "Your Money or Your Life" — Google and AI models weight author expertise and source trust heavily.

- **`Organization.sameAs` is an empty array.** Populate it with every authoritative brand profile you control (LinkedIn, X/Twitter, Instagram, YouTube, Crunchbase, and — critically — a **Wikidata** entry). `sameAs` is the primary signal that ties your site to a real-world entity for both Google's Knowledge Graph and LLM entity resolution.
- Add `Organization` `contactPoint`, `address`, `foundingDate`, and `logo` dimensions consistently (currently only partially present; `/about` has a contactPoint but the homepage/global graph does not).
- Add **author / medical-reviewer** attribution to monographs and educational content: `author`, `reviewedBy` (a `Person` with credentials), `dateModified`, and `lastReviewed` on `MedicalWebPage`. Even a named scientific editor with a short bio page materially improves trust.
- Add a real **About/Editorial-standards page** describing sourcing methodology, reference tiers, and review process, and link it from every monograph.

### P1-2. Structured-data gaps
Add these schema types (all currently missing or partial):

- **FAQPage** JSON-LD on `/research/faq`, `/peptide-101`, `/shipping`, `/become-agent`, and city pages. This is one of the highest-yield schema types for both rich results and AI answer extraction. (Currently only `research/faq` and `research/search` reference Question markup — extend and verify it emits valid `FAQPage`.)
- **DefinedTermSet / DefinedTerm** for the glossary (`/research/glossary`). LLMs love clean term→definition pairs; this makes your glossary directly citable.
- **Dataset** schema for the compound database (`/research/catalog` / `/research/a-z`) — signals to Google Dataset Search and AI that you publish a structured research dataset.
- **HowTo** schema for reconstitution/reconstitution-calculator and any step-by-step guides under `/research/calculators`.
- **BreadcrumbList** site-wide (currently only on monographs) — add to research sub-pages, city pages, and info pages.
- **Product / Offer** consideration for storefront items — note payments are off-platform and content is RUO, so use carefully; if used, mark availability/price honestly and keep the RUO disclaimer in schema `description`.
- **CollectionPage `hasPart` / `ItemList`** on hub pages to enumerate child items, so crawlers understand the set without JS.

### P1-3. Programmatic city pages risk being seen as thin / doorway pages
The state+city pages are great for coverage but if they share near-identical boilerplate ("Pep Nation Lab supplies research-grade peptides across N cities in {State}…"), Google may classify them as thin or doorway content and suppress or penalize them.

**Fix:** Give each city page genuinely unique, useful content — local shipping notes, region-specific research institutions, distinct intro copy, a different curated compound list, or local FAQ. If unique content per city isn't feasible, consolidate to state-level pages only and prune the thinnest city pages from the sitemap.

### P1-4. Internal linking & anchor text
Beyond the homepage (P0-1), audit that internal links use descriptive anchor text (not "click here", not empty). Build a crawlable **HTML hub-and-spoke**: homepage → research areas → compounds → related compounds, with contextual cross-links. Add a visible footer sitemap linking the top research areas, calculators, and key monographs from every page.

### P1-5. Core Web Vitals / performance
- The homepage LCP is a large flat PNG served from Supabase storage (`pep-nation-landing.png`, ~941×1672). Optimize: serve WebP/AVIF via `next/image`, set explicit width/height, `priority`, and ideally replace with HTML text + smaller decorative imagery.
- The root layout mounts many client providers (`FlashSaleBanner`, `GlobalCallListener`, `SessionKeepalive`, `PWAEnforcer`, `FirstRunNotificationPrompt`, several toasters/banners) plus four global CSS files — this inflates the JS/CSS on every route including landing pages. Defer or route-scope anything not needed on public marketing pages.
- Run PageSpeed Insights / Lighthouse on `/`, `/research`, and a monograph; target LCP < 2.5s, INP < 200ms, CLS < 0.1.

### P1-6. Search Console / Bing / indexing hygiene
- Verify the domain in **Google Search Console** and **Bing Webmaster Tools**; submit `sitemap.xml`.
- Add **IndexNow** (Bing/Yandex instant indexing) — trivial to wire from the same place the sitemap is generated; pings search engines the moment a compound is added/updated.
- Monitor Coverage/Enhancements reports for the client-render pages (P0-2) — they'll likely show up as "Crawled - currently not indexed" or thin, which is the signal that SSR is needed.

## P2 — Polish & Ongoing

- **Allow zoom:** `viewport` sets `maximum-scale=1, user-scalable=no`. Google's mobile guidelines and accessibility (WCAG) discourage disabling zoom; it's a minor mobile-usability ding. Consider removing `user-scalable=no`.
- **Canonical consistency:** the layout/page emit `https://pepnationlab.com/` in metadata but the live homepage canonical is `https://pepnationlab.com` (no trailing slash). Pick one form and use it everywhere (including sitemap and internal links) to avoid canonical dilution.
- **Sitemap scaling:** a single `sitemap.xml` is fine under 50k URLs, but split into a **sitemap index** (pages / compounds / cities as separate child sitemaps) for cleaner reporting, and add an **image sitemap** for product/compound imagery. Ensure `lastmod` reflects real content changes (compounds already use `updated_at` — good).
- **Image SEO:** ensure every product/compound image has descriptive, keyworded `alt` text and is served in a modern format via `next/image`.
- **Open Graph coverage:** per-compound OG images exist (good) — extend dynamic OG images to research-area, city, and calculator pages so social/AI previews are unique.
- **Fresh content engine:** add a `/blog` or `/research/updates` with regularly published, cited articles (mechanism deep-dives, new-compound announcements, evidence reviews). Topical freshness and depth build authority and give AI models more citable surface area. `new-additions` and `timeline` pages already hint at this — expand.
- **RSS/feed discovery:** link `feed.xml` via `<link rel="alternate" type="application/rss+xml">` in `<head>` so feed readers and crawlers discover it.
- **Accessibility = SEO:** empty links (homepage), missing headings hierarchy, and zoom-disable all overlap accessibility and SEO. An a11y pass (axe/Lighthouse) will surface several dual-purpose wins.
- **404 status codes:** confirm `not-found.tsx` returns HTTP 404 (not 200) so soft-404s don't accumulate.

## Dedicated Section: Being Found & Recommended by AI (ChatGPT, Claude, Perplexity, Gemini, Grok)

"Answer-engine optimization" (AEO/GEO) overlaps with SEO but has distinct levers. Ranked by impact:

1. **Server-render the actual content (see P0-2).** This is #1 for AI. Most AI crawlers do not run JavaScript. If a monograph's mechanism, evidence, and facts are only in client-rendered tabs, the model never sees them. Your `llms.txt` + markdown endpoints are an excellent mitigation and should stay — but make sure `/api/llm/compound/[slug]` is actually reachable by bots (P0-3) and that the canonical HTML pages also carry the prose.

2. **Keep and enrich `llms.txt` / `llms-full.txt`.** You're ahead of the field here. Improve it by:
   - Linking the **HTML** monograph URLs (`/research/[slug]`) alongside the API markdown ones, so models can cite the human page.
   - Adding sections for key non-compound pages: calculators, glossary, comparison tool, about/methodology, shipping/compliance.
   - Adding a one-line factual description per entry (you already do category — add a short summary).
   - Keeping it auto-generated from the DB (already the case) so it never goes stale.

3. **Entity clarity & off-site presence.** LLMs resolve and trust *entities*. Establish:
   - A **Wikidata** item for Pep Nation Lab, and populate `Organization.sameAs` with it plus real social profiles.
   - Consistent NAP (name/description/claims) everywhere — same one-sentence description of what the company is, repeated across site, schema, and profiles.
   - Third-party mentions (industry directories, press, reputable forums). AI recommendation is heavily influenced by corroborating off-site sources, not just your own site.

4. **Extractable, self-contained answers.** Models prefer content they can lift as a clean answer:
   - FAQ blocks with direct question→answer pairs (+ FAQPage schema).
   - Definition boxes (glossary + DefinedTerm schema).
   - Comparison tables (your `/research/compare` — ensure it's server-rendered and includes a plain HTML table).
   - "Key facts" summary blocks at the top of each monograph (half-life, sequence, mechanism, evidence tier) in plain HTML.

5. **Structured data is machine-readable trust.** Your `MedicalSubstance`, `speakable`, and `MedicalWebPage` markup already help. Add `FAQPage`, `DefinedTermSet`, `Dataset`, `author`/`reviewedBy`, and `dateModified` (see P1-1, P1-2).

6. **Don't block the AI bots (P0-3).** Explicitly allow `GPTBot`, `ClaudeBot`, `PerplexityBot`, `Google-Extended`, `CCBot` in `robots.ts` and confirm no edge firewall challenges them. This is a business decision — but you can't be recommended by a model whose crawler you block.

7. **Freshness + citations.** AI answer engines favor recently-updated, well-cited pages. Your monographs cite references with confidence bands (excellent). Surface `dateModified` in the HTML and schema, and keep publishing new/updated content.

8. **Speakable & concise summaries** (already partially done) help voice assistants and are cheap to extend to more pages.
